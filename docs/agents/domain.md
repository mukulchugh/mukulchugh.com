# Domain docs

Use a single-context layout: root CONTEXT.md and docs/adr/.

Before exploration, read existing CONTEXT.md and relevant ADRs. If CONTEXT-MAP.md exists later, follow its relevant context pointers.

Missing documentation is not a blocker. Proceed without scaffolding; domain-modeling creates documentation when decisions are resolved.

Use established glossary terms. Explicitly flag proposals that contradict an existing ADR rather than silently overriding it.
